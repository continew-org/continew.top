# ContiNew 文档写作技能

本技能沉淀 ContiNew 开源社区文档的可执行写作规范，供 AI 智能体撰写、重写或评审各项目仓库 `docs/` 目录文档时遵循。各项目仓库的 AGENTS.md「文档（docs/）」一节引用本文件的精简版，**本文件为事实源全本**。

## 何时使用

- 在某项目仓库（continew-starter / continew-admin / continew-app）的 `docs/` 下新建、重写或评审文档；
- 将旧站（VitePress）文档迁移为 Fumadocs 格式；
- 批量统一文档风格时。

## 一、目录组织

按「叙事式学习路径」组织，而非按代码模块平铺：

```
docs/
├── index.mdx              # 分区入口（着陆页）：是什么一句话 + 导航卡片，不复述正文
├── meta.json              # 分区标题、图标、页面顺序；root 分区标 root: true
├── guide/                 # 指南：introduction（是什么/解决什么）→ quick-start → configuration
├── modules/               # 功能模块：单实现一版 .mdx；多实现为目录（index 入口 + 子实现各一篇）
└── reference/             # 参考：properties（配置项）/ dependencies / faq / changelog
```

原则：

- 用户的阅读路径是「快速开始 → 引入依赖 → 查某功能完整用法」，组织方式要服务于这条路径；
- **多实现模块拆分**：含多个子实现的模块（如 cache、auth、extension），按「目录 + 子实现各一篇 + 模块 index 入口」组织，让侧边栏可直达具体组件；单实现模块保持单篇；
- **Root Folder**：每个项目分区在 meta.json 标 `root: true`，构成官网侧边栏顶部的项目切换器；
- **模块 README 做导航卡片**：多模块项目的代码模块内保留简版 `README.md`，只放「是什么 + 坐标 + 一句话用法 + 完整文档链接」，不复述完整文档。

## 二、frontmatter（必填）

```mdx
---
title: 页面标题
description: 一句话描述本页解决什么问题（用于 SEO、搜索摘要、OG 图片、llms.txt）
---
```

- `title` 用**纯中文**（如「数据权限」「多租户」），模块英文名放 `description`；
- `description` 一句话说明价值，不空、不复述标题。

## 三、链接策略

- **跨模块/跨分区引用**：用绝对路径 `/docs/<project>/...`（如 `/docs/starter/modules/cache`），保证官网汇聚渲染时正确；
- **同模块/同目录内引用**：用相对链接（如 `./redisson`、`../guide/quick-start`），GitHub 仓库内裸看时也能跳转；
- 外部链接给完整 URL。

## 四、写作风格规范（活人感写作 · 技术文档版）

技术文档同样是人在说话：这个人知道实现细节，也知道哪里会踩坑，愿意把来龙去脉讲清楚。不喊口号、不替读者感动、不把常识包装成洞察。判断可以直接下，但依据要放在附近。

### 硬禁令

| 禁令 | 说明 |
|:-----|:-----|
| 不用破折号 `——` | 改成分句、括号或另起一句 |
| 不用提示性冒号 | 「说明：」「通用模式：」这类冒号禁止。冒号只用于引出原话；代码块与配置键内的冒号不受限 |
| 不写翻案腔 | 「不是 A，而是 B」「值得注意的是」「需要注意的是」「说白了」「先说结论」全部禁用 |
| 不写商业与模型黑话 | 赋能、一站式、无缝、极致、助力、打造、综上所述 |
| 不把动词名词化 | 「完成了对配置的加载」→「加载配置」；「实现了效率的提升」→「快了多少」 |
| 不给抽象名词配具体动词抒情 | 时间不会保管细节，架构不会承载梦想 |
| 不在末段摘要全文 | 讲完就停，不强装升华 |

### 段落推进

- 一段只做一件事：讲动作、补背景、解释原因、承认疑点、给判断，选一个；
- 新段落必须带来一样新东西：新的事实、例子、区别、后果都算，同一观点换说法不算；
- 后一段接住前一段留下的问题，不用「更深一层」「真正的问题」这类路标；
- 先让主语和动作出现，再接时间、原因、条件。

### 材料要求（事实源优先级）

每条结论必须能指到一样看得见的东西：**starter 源码（类名 / 默认值 / 异常）> continew-admin 实际用法（示例 / 组合 / 最佳实践）> 上游官方文档**。

- admin 排第二而不是第一：它是消费方，可能只用默认路径，也可能用自己的扩展点覆盖了默认行为，API 签名必须以 starter 源码为准；
- **示例场景去业务化**：API 与配置键可取 admin 的真实形态，场景换成通用的。不要把 admin 的 `sys_user`、`ignore-menus: 1050` 这类业务数据贴进来；
- **配置项归 starter，配置值归 admin**：框架级配置项的定义写 starter 文档；admin 给这些键填的具体值写 admin 文档；
- 每个模块文档末尾加「完整参考实现」链接，指向 admin 仓库具体文件，供读者看工程级用法。

## 五、组件用法

代码块标注语言（```xml、```yaml、```java、```bash），命令给可直接复制执行的完整形式；配置项/类名/注解/坐标用行内代码（`）包裹。

需要处使用 Fumadocs 组件：

```mdx
<Cards>
  <Card title="标题" description="一句话" href="/docs/starter/guide/quick-start" />
</Cards>

<Callout type="info|warn|error">提示内容</Callout>

<Tabs items={['实现A', '实现B']}>
  <Tab value="实现A">...</Tab>
  <Tab value="实现B">...</Tab>
</Tabs>

<Steps>
  <Step>第一步</Step>
  <Step>第二步</Step>
</Steps>
```

注意：`<Card>` 的 `href` 不要指向不存在的页面；依赖坐标给 Maven `<dependency>` 形式，`groupId` 为 `top.continew.starter`，不写 `<version>`（由 BOM 统一供给）。

## 六、版本标注

- 示例的版本号给**具体值**（如 `2.17.0`），不给 `${占位符}`，并附 Maven Central 查询链接；
- 不写「当前版本 x.x.x」「历史大版本将随版本锁定提供」这类易过时或功能预告表述；
- 为大版本冻结做准备：版本相关内容标注适用范围（如「2.x 基于 Spring Boot 3.x」）。

## 自检清单（写完逐条过）

- [ ] 全文无 `——`
- [ ] 无提示性冒号（代码块与配置键除外）
- [ ] 无「不是……而是……」「值得注意的是」等翻案句式
- [ ] 无赋能/一站式/无缝/极致类黑话
- [ ] 每个判断后面跟了依据（类名/配置键/默认值/报错串/真实用法）
- [ ] 每段都推进了新信息，没有换说法重复
- [ ] 末段没有摘要全文
- [ ] 示例能直接复制运行（版本号给具体值）
- [ ] 配置项、类名、默认值与源码一致
- [ ] 跨模块链接用绝对路径、同模块内用相对链接
- [ ] frontmatter 含纯中文 title 与一句话 description
